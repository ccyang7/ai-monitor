# API 概览

平台对外公开的接口如下。网页端使用的查询接口属于内部实现，不在对外契约范围内。

| 方法 | 路径 | 认证 | 用途 |
| --- | --- | --- | --- |
| GET | `/health` | 无 | 健康检查 |
| POST | `/api/v1/logs` | `X-API-Key` | 上报一次模型调用 |

## 服务地址

平台默认监听 `8001` 端口，实际地址以平台部署方提供的为准：

```text
http://<平台地址>:8001
```

## 健康检查

```bash
curl http://<平台地址>:8001/health
# {"status":"ok"}
```

> ⚠️ **健康检查接口位于根路径**，不在 `/api/v1` 下。业务接口均以 `/api/v1/` 为前缀，健康检查是唯一例外。

如果平台与 AI 项目不在同一台机器上，平台必须以 `--host 0.0.0.0` 启动，并放行对应端口。uvicorn 默认仅监听 `127.0.0.1`，未监听对外地址时，接入方会收到「连接被拒绝」，而平台日志中没有对应请求，表明请求未到达平台。

## 认证方式

| 场景 | 凭证 | 请求头 |
| --- | --- | --- |
| 网页端操作 | 登录后获取的 JWT | `Authorization: Bearer <token>` |
| 程序上报调用记录 | 项目的 API Key | `X-API-Key: proj_...` |

上报接口仅接受 `X-API-Key`，不接受 JWT。两种凭证用途不同：前者用于程序上报，后者用于用户登录。

API Key 在创建项目时展示一次，平台仅存储其哈希，无法还原明文。吊销与重新生成见 [项目设置与 Key](/docs/guide/project-settings)。

## 通用约定

- 请求体使用 `Content-Type: application/json`，编码为 UTF-8。
- 时间使用 ISO 8601 格式。**不带时区的时间按 UTC 解释**，规则与示例见 [上报接口的时间规则](/docs/api/ingest#时间规则)。
- 创建成功返回 **201**，响应体为 JSON。
- 请求失败返回 4xx 或 5xx，响应体中的 `detail` 字段为错误原因。各状态码的含义与排查顺序见 [错误码与处理](/docs/api/errors)。
- **请求路径不应以斜杠结尾**：`/api/v1/logs/` 会返回 307 重定向，部分 HTTP 客户端默认不跟随重定向，会导致上报静默失败。
