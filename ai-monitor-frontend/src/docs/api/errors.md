# 错误码与处理

上报接口可能返回以下状态码：

| HTTP | 含义 | 处理方式 |
| --- | --- | --- |
| **201** | 成功 | 无需处理 |
| **401** | API Key 缺失、无效、已吊销或已过期 | 检查 `.env` 中的 Key，见下文 |
| **422** | 字段不合法 | 响应体 `detail` 包含具体字段与原因，按提示修改 |
| **404** | 路径错误 | 检查 URL 是否为 `/api/v1/logs`（**复数**），而非 `/api/v1/log` |
| **405** | HTTP 方法错误 | 上报使用 **POST** |
| **307** | 路径末尾多余斜杠 | 移除 URL 末尾的斜杠 |
| **5xx** | 平台故障 | 记录本地日志并**丢弃该条记录**，不得重试阻塞业务 |

## 401 与 422 的处理顺序

平台**先验证 API Key，再验证字段**。收到 401 时，请求体字段尚未被检查，因此不能据此判断字段是否正确。

处理顺序：

1. 先解决 401。收到 422 或 201 表示 Key 已通过验证。
2. 再解决 422。此时的错误信息才反映字段问题。

持续返回 401 时，应检查 API Key，而非修改请求体。

## 401：Key 的四种失败原因不区分

401 响应体格式：

```json
{"detail":"API Key 无效或已失效"}
```

API Key 缺失、不存在、已吊销或已过期时，均返回同一条信息，响应体不包含 API Key 内容。

排查顺序：

1. **首尾存在空白字符**：从网页复制的 Key 可能包含换行或空格。`proj_xxx` 末尾带一个空格即为无效 Key，且外观难以区分。
2. **Key 已吊销**：在项目「设置」页查看。**已吊销的 Key 不会显示在列表中**，列表中不存在即为已吊销，详见 [项目设置与 Key](/docs/guide/project-settings)。
3. **环境变量未加载**：`.env` 新增变量后未重启进程，或变量名拼写错误时，接入代码会直接返回，不发送请求。

区分「Key 问题」与「环境变量读取问题」的方法：使用同一 Key 执行 curl（见 [快速开始](/docs/getting-started/quickstart)）。curl 成功表示 Key 有效，问题在代码读取配置；curl 同样返回 401 表示 Key 本身无效。

## 422：`detail` 为数组

一次请求可能同时返回多个字段错误。`loc` 表示问题位置（`["body","latency"]` 即请求体中的 `latency`），`msg` 为原因。

```json
{"detail":[{"type":"missing","loc":["body","latency"],"msg":"Field required","input":{...}}]}
```

常见类型：

- **字段缺失**：未提供必填字段
- **类型错误**：`latency` 传入了字符串
- **超出范围**：传入负数
- **取值不在枚举内**：`status` 传入了 `failed`（仅支持 `success` / `error`）
- **字段矛盾**：`cache_hit_tokens` 大于 `input_tokens`

完整字段规则见 [上报接口](/docs/api/ingest#请求体字段)。

## 307：路径末尾多余斜杠

访问 `/api/v1/logs/` 会返回 307 重定向。多数 HTTP 客户端（httpx、requests、axios、okhttp）默认跟随重定向；部分客户端默认不跟随，导致上报静默失败。

请求路径请直接使用 `/api/v1/logs`，不要附加末尾斜杠。

## 5xx：丢弃记录

平台故障时，按「上报不阻塞业务」原则处理：记录一条本地日志，丢弃该条记录，不重试。

## 上报没报错，但平台上一条记录都没有

上报实现会捕获异常并静默处理，因此上报失败不会在业务侧报错。请按以下顺序排查：

1. **先用 curl 确认平台侧通路正常**。curl 成功而业务代码失败，问题在代码侧（第 2、3 项）；curl 同样失败，问题在网络或 API Key。
2. **检查 API Key 是否加载**：环境变量为空时，示例代码会直接返回，不发送请求。
3. **检查本地日志中是否记录「上报失败」**。
4. **检查 URL**：常见错误为缺少 `/api/v1`，或末尾多余斜杠。

更多场景见 [常见问题 · 接入与上报](/docs/faq/integration)。

## 平台在别的机器上连不上

按以下顺序检查：

1. 平台是否以 `--host 0.0.0.0` 启动（uvicorn 默认仅监听回环地址）
2. 防火墙是否放行对应端口
3. 两台机器的网络是否互通

典型表现为「连接被拒绝」且平台日志中没有对应请求，通常由第 1 项导致。
