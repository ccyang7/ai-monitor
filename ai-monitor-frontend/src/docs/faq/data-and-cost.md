# 数据与成本

## 首页卡片一直是「未接入数据」？

两种可能：尚未接入，或已接入但未成功上报。请先按 [接入验收清单](/docs/getting-started/verify) 的五项检查；仍无数据时，按 [接入与上报](/docs/faq/integration) 排查。

## 有调用记录，成本列却一直是「—」？

模型名未匹配价格表。请在模型管理页查看顶部橙色提示条，点击模型名补充价格，见 [模型与价格](/docs/guide/models#页顶的橙色提示条)。

补充价格仅对之后的调用生效，历史记录的「—」不会改变，见下文。

## 成本与厂商账单不一致？

常见原因如下：

- **缓存价差异**：未配置缓存价或未上报命中数量时，命中部分按输入价计算，结果偏高
- **价格快照**：修改价格不重算历史记录
- **Token 用量本身存在偏差**：厂商计数也存在误差

成本为**估算**，不用于对账。详见 [基础概念](/docs/guide/concepts#预估成本是估算不是账单) 与 [模型与价格](/docs/guide/models#页顶的橙色提示条)。

## 记录的时间相差 8 小时？

这是**上报侧**的问题：`timestamp` 未带时区，被按 UTC 解释。平台展示直接采用上报的时间，修正上报侧后即正常。规则见 [上报接口的时间规则](/docs/api/ingest#时间规则)。

## 补报的历史数据在列表中的位置？

按「调用发生的时间」排序，落在对应时间位置，不会排在最上方。见 [调用日志](/docs/guide/logs#分页与排序)。

## 修改价格后，为什么历史记录的成本没变？

成本为**写入时的快照**：每条记录在上报时按当时价格计算并保存，之后修改价格不会重算。

## 「—」「¥0.00」与「<¥0.01」的区别？

- `—`：未匹配到价格，无法计算
- `¥0.00`：已计算，结果为 0（如免费模型）
- `<¥0.01`：已计算，金额大于 0 但不足半分钱（按两位小数会显示成 `¥0.00`）

详见 [基础概念](/docs/guide/concepts#预估成本是估算不是账单)。

## 缓存命中价留空与填 0 的区别？

- 留空：该模型没有缓存价，命中部分按输入价计算
- 填 0：该模型有缓存价，且缓存免费

见 [模型与价格](/docs/guide/models#三档价格怎么填)。

## 修改内置模型的价格，会影响其他用户吗？

不会。「修改」生成的是你自己的副本，改动仅影响自己项目的成本估算，内置模型与其他用户不受影响。

## 提示条消失了，但历史成本仍为「—」？

提示条判断当前能否匹配价格，成本为写入时的快照，两者不同步。补充价格仅对之后的调用生效。
