# 接入与上报

## 上报代码没报错，但平台上一条记录都没有？

上报实现会捕获并忽略异常，因此上报失败不会在业务侧报错。请按以下顺序排查：

1. **先确认平台侧通路正常**：使用 curl 直接发送一条记录（见 [快速开始](/docs/getting-started/quickstart)）。curl 成功而业务代码失败，问题在代码侧；curl 同样失败，问题在网络或 API Key
2. **检查 API Key 是否加载**：`.env` 新增变量后未重启进程，或变量名拼写错误时，接入代码会直接返回，不发送请求
3. **检查本地日志中是否记录「上报失败」**
4. **检查 URL**：常见错误为缺少 `/api/v1`，或末尾多余斜杠（307）

完整排查路径见 [错误码与处理](/docs/api/errors#上报没报错但平台上一条记录都没有)。

## 一直返回 401，但 Key 是从平台复制的？

按可能性排序：

1. **首尾存在空白字符**：从网页复制的 Key 可能包含换行或空格。Key 末尾带一个空格即为无效 Key，且外观难以区分
2. **Key 已吊销**：在项目「设置」页查看，**已吊销的 Key 不会显示在列表中**，列表中不存在即表示已吊销

> 区分「Key 问题」与「环境变量读取问题」最快的办法是使用同一把 Key 执行 curl。curl 成功表示 Key 有效，问题在代码读取配置；curl 返回 401 表示 Key 本身无效。

## 平台在别的机器上，连不上怎么办？

按以下顺序检查：

1. 平台是否以 `--host 0.0.0.0` 启动（uvicorn 默认仅监听回环地址）
2. 防火墙是否放行对应端口
3. 两台机器的网络是否互通

典型表现为**连接被拒绝，且平台日志中没有对应请求**，通常由第 1 项导致。详见 [错误码与处理](/docs/api/errors#平台在别的机器上连不上)。

## 上报的数据会不会拖慢业务接口？

不会。上报在后台线程中发送，主流程不等待其结果，[把上报写进代码](/docs/getting-started/integration) 中的四条要求即用于保证这一点。

平台不可用时，接入方的 AI 项目照常运行，[接入验收清单](/docs/getting-started/verify) 第 4 项验证的即为该行为。

## 一次用户操作，平台上出现多条记录？

通常是重试所致。接入方的 AI 项目对模型调用进行重试时（更换提示词重试、超时重试等），每次重试均为一次真实的模型调用并产生实际计费，因此各上报一条记录。

判断标准：厂商账单中扣费几次，平台上就应有几条记录。

## 能同时接入多个 AI 项目吗？

能。一个 AI 项目对应一个平台项目与一把 API Key。数据按项目完全隔离，项目之间无法查看彼此的数据，隔离由服务端保证。

每个账号最多 3 个活跃项目，见 [首页与项目](/docs/guide/home-and-projects)。
