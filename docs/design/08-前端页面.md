## 1. 技术栈与目录结构

Vue 3 + TypeScript + Vite + Naive UI + ECharts。

```text
ai-monitor-frontend/
├── src/
│   ├── main.ts                 入口
│   ├── App.vue
│   ├── router/                 路由
│   ├── api/                    接口封装（每个领域一个文件）
│   ├── stores/                 Pinia 状态
│   ├── views/                  页面（与路由一一对应）
│   ├── components/             通用组件（TrendChart 等）
│   ├── types/                  TypeScript 类型（与后端 schema 对应）
│   └── utils/
```

> ⚠️ **实现修订（阶段 10）：UI 库是 Naive UI 不是 Ant Design Vue。**
> Ant Design Vue 一次都没装。原型的控件本来就是手写的，最终只在需要
> 「焦点陷阱 / Esc / 滚动锁定」这类**行为**的地方引入 Naive UI（`NModal`、`NDrawer`），
> 长相仍然由 `styles/` 里那套设计令牌控制。

> ⚠️ **实现修订（阶段 11）：没有 `charts/` 目录。**
> 图表只抽了一个 `components/TrendChart.vue`（见 §5），单独开一层目录不值当。

> **`api/` 按领域分文件**（`auth.ts`、`projects.ts`、`logs.ts`…），
> 和[后端设计](README.md#2-目录结构)保持一致的划分方式。

### 2.1 布局结构

```text
登录页：独立布局（无导航）

主应用：左侧导航 + 顶栏 + 内容区
  左侧导航：首页 / 模型管理 / AI 助手
  进入某个项目后：导航下方展开该项目子菜单
```

> **AI 助手是全局的，不属于任何项目** —— 所以它在主导航里，不在项目子菜单里。
> 这与[需求文档 18 章](../轻量级大模型使用监控与智能分析平台.md)的"全局助手"定位一致。

### 2.2 ⚠️ 日志详情用抽屉，不用独立路由

列表 → 详情如果用路由跳转，用户看完要返回列表时会丢失筛选条件和页码。

**用 Drawer 组件**：在列表页上滑出详情，关闭后筛选状态还在。

> 这是列表-详情交互的常见设计。
> 如果确实需要"详情可分享链接"，再考虑路由 —— V1 不需要。

### 2.3 异常分析页：卡片流，不是表格

每条异常要讲清「实际值 vs 基线 vs 倍数」，塞进表格会挤成一团 —— 所以是一列卡片。

几条要守住的规矩：

- **整张卡就是点进详情的入口，没有「查看详情」按钮**：每行右边站一个按钮，扫一眼
  满屏都是按钮，而左边的类型色条 + 标题已经把「哪类、多严重」说完了。可点与否由
  `item.log_id !== null` 决定（`is-link` 类 + `role="button"` + `tabindex="0"`），
  **不按 `type` 判断** —— 以后多一类判定，这里不用改。
  窗口类异常（`error_rate`）没有 `log_id`，既不给指针光标也不给悬停浮起，
  点下去自然是没反应的 —— 画成可点的样子却又没反应，比不给反馈更让人困惑。
- **描述由分段的 `Segment[]` 拼，不用 `v-html`**：`error_message` 是接入方传上来的，
  拼成一个字符串再交给 `v-html`，等于让它有机会变成标签。
- **样本不足的模型合成一块**，一个项目就一条：首行给结论（「N 个模型样本不够，
  用量与延迟暂时不判定」），下面每个模型一行「最近 7 天 X 次 · 还差 M 次开始判定」。
  它长得和异常卡不一样（虚线框 + 纯灰，一个绿色都没有），因为它回答的是
  「哪里还看不出来」，不能被画成「一切正常」的样子（见 §6.2、§6.3）。
  逐模型各写一段解释是重复劳动，只会把屏幕填满。
- **分页器只在多于一页时出现**：全灰的「上一页 1 下一页」占的是屏幕上的实位。

### 2.4 异常判定标准那张卡：开关直接对应 NULL

异常页顶部那张卡（`AnomalySettingsCard`）**默认收起成一行摘要**：

```text
异常判定标准   Token 5 倍 · 延迟 3 倍 · 错误率 20%   [按系统默认]        ⌄
```

它一年也改不了两次，长期占着上半屏不值当。展开才是表单（[设计 05 §4.3](05-异常分析.md) 是它背后的接口）。

三项各带一个**「跟随默认」开关** —— 这个开关不是装饰，它就是库里的 `NULL`：

| 开关 | 输入框 | 存进库里的值 |
|---|---|---|
| 开（默认） | 置灰，显示当前默认值 | `NULL` —— 以后系统改默认，它跟着变 |
| 关 | 可编辑 | 具体数字 —— **固定住**，不再跟着系统走 |

> **为什么不做成「输入框一直可编辑」**：那样用户没法表达「我要跟随默认」。
> 填了 5（正好等于默认值）和「跟随默认（5）」在界面上长得一模一样，语义却完全不同。

**关掉开关却填了个和默认一样的数**时，输入框下面会多一句琥珀色提示
（「填的和默认值一样，但这一项会被固定住」）—— 这是全站唯一能看出
「固定成 5」和「跟随默认（5）」不一样的地方。

其余几处讲究：

- **错误率按百分比填、按百分比显示**，发请求时才 ÷100 变成 0.2。
  页面别处写的都是「20%」，这里让人填 0.2 只会被当成填错
- **范围先在前端挡一道**（倍数 `1.5 ~ 20`、错误率 `5% ~ 100%`），提示写成
  「要在 1.5 ~ 20 倍之间」。后端也会拒（422），但 422 的原文是
  「Input should be less than or equal to 20」，用户看不出说的是哪个框
- **「全部恢复默认」= 三个开关都打开再保存**，走的是同一个 `save()`；
  没有自定义项时按钮是灰的
- ⚠️ **保存成功后必须重新拉异常列表，并回到第 1 页。** 阈值改了历史是被**重判**的，
  不重拉的话屏幕上还是旧标准的结果 —— 用户刚被告知「历史会重判」，看到的却没变，
  会以为保存没生效。回第 1 页是因为条数变了，停在第 3 页很可能是一片空白
- 卡上那句「保存后**历史数据会立刻按新标准重判**，列表可能一下多出或少了若干条」
  不能省（[需求 05 §2.4](../requirements/05-异常分析.md)）：不写，用户看到列表突然多出几十条，
  第一反应是「平台算错了」
- **「基线是什么」只在展开后的说明里讲一次**。页面上原本还有一条常驻的绿色说明块，
  位置比卡片还显眼，可它是读一遍就够的常识，天天占着页面最上方 —— 现在并进卡片的
  展开说明（「基线 = 同一个模型最近 7 天的平均水平……」），收起时整个页面只剩一行摘要

> ⚠️ **`<input type="number">` 上的 `v-model` 会自动把值转成 `number`** ——
> 输入框清空时又变回字符串 `''`。所以草稿字段的类型是 `string | number`，
> 用之前统一 `String()` 一下。踩过一次：直接写 `input.trim()`，
> 用户一敲数字就抛 `state.input.trim is not a function`，整个组件渲染挂掉
> （`typecheck` 查不出来 —— 类型写的是 `string`，运行时给的是数字）。

## 3. API 封装

### 3.1 统一实例

用 axios 创建一个实例，统一处理：

```text
① baseURL = /api/v1    （开发环境由 Vite proxy 转发到后端）
② 请求拦截器：自动带 Authorization: Bearer <token>
③ 响应拦截器：
     401 → 清除本地 token，跳转登录页
     其他错误 → 弹出统一的错误提示
```

### 3.2 ⚠️ 401 处理要避免无限跳转

登录接口本身返回 401（密码错误）时，如果拦截器无脑跳转登录页，会造成循环。

**做法**：判断请求 URL 是否是登录/注册接口，是则跳过跳转逻辑，让业务层处理错误。

### 3.3 类型定义

`types/` 下的类型定义**与后端 `schemas/` 一一对应**：

```typescript
interface LogItem {
  id: number
  model: string
  total_tokens: number
  ...
}
```

> **字段名保持 snake_case**（与后端 JSON 一致）—— 不要在前端转成 camelCase。
> 转换会带来"两边对不上"的排查成本，而收益只是"符合前端习惯"。
>
> 需求文档 9.5 定的"字段命名以 snake_case 为契约"，前端也要遵守。

## 4. 状态管理（Pinia）

### 4.1 需要全局状态的只有两处

| Store | 内容 |
|---|---|
| `auth` | token、当前用户信息 |
| `project` | 当前项目信息（进入项目后加载） |

> **其余数据不入 store** —— 页面自己的数据请求完直接用，用完就扔。
>
> 很多人一上手就建一堆 store，结果是"数据在哪"变成猜谜。
> **规则：只有多个页面需要共享的数据才进 store。**

### 4.2 token 的存储

```text
localStorage    ← 刷新页面不丢
```

> ⚠️ 注意 localStorage 有 XSS 风险（脚本可读）。V1 接受（单体应用、自己控制的内容）。
> 更安全的是 httpOnly cookie，但它需要后端配合 CSRF 防护 —— 记在已知取舍里。

## 5. 图表封装

ECharts 在每个页面重复初始化的代码很多，抽一个通用组件：

```text
components/TrendChart.vue     趋势图（折/柱由 type 属性切换）
```

> ⚠️ **实现修订（阶段 11）：原计划拆成 LineChart / BarChart / PieChart 三个文件，实际只做了一个。**
> 三个组件的初始化、resize、销毁逻辑一字不差，差别只在 `series.type` 和一个
> `boundaryGap` —— 拆开就是三份同样的代码等着各自长歪。饼图等真用到（阶段 11
> 的模型占比页）再说，用不上就不写。

### 5.1 ⚠️ 必须处理的两个点

| 点 | 做法 |
|---|---|
| 容器尺寸变化 | 监听 resize，调 `chart.resize()` |
| 组件卸载 | `chart.dispose()`，否则内存泄漏 |

> ECharts 实例不销毁是前端最常见的内存泄漏之一 —— 反复进出页面会越来越卡。

> **实现补充**：容器尺寸用 `ResizeObserver` 盯容器本身而不是 `window` 的 resize ——
> 侧边栏折叠之类的变化不动窗口尺寸，光听 window 会漏。销毁时记得
> `observer.disconnect()`，否则观察者自己就是一份泄漏。

> **颜色**：canvas 不认 CSS 变量，ECharts 的配色是从 `getComputedStyle` 里把
> `tokens.css` 的值读出来用的。抄一份写死的话，改配色时要改两处，而漏掉的那处
> 不会报错，只会在页面上难看。

### 5.2 图表数据来源

**直接消费后端返回的 `series` 数组**，前端不做聚合计算。

> 这要求后端把"空日期补零"做好（见[设计 03 §3.4](03-项目监控中心.md)）——
> 前端拿到就能直接画。**复杂逻辑放在后端**，前端只负责展示。

> ⚠️ **`series[].date` 是标签字符串，不是时刻**（见[设计 03 §2.3](03-项目监控中心.md)）：
> 按天是 `"2026-10-01"`，按小时是 `"2026-10-12T14:00"`。组件按「含不含 `T`」
> 区分格式（轴取短的，tooltip 补全），**不要 `new Date()` 去解析它** ——
> 解析就得同时面对 `'2026-10-01'` 按 UTC、`'2026-10-01T00:00:00'` 按本地
> 两套规则，而这里要的只是一个显示用的短标签。

> ⚠️ **实现修订（2026-10-12）：概览页的趋势图改用柱状图。**
>
> 折线图会在两个离散的数据点之间画斜线，那是**凭空插值的暗示**：按天统计时
> 一天只有一个数，10-06 到 10-07 之间那条斜线却在暗示「10-06 中午大概是多少」——
> 可那个时刻没人采样，斜线上的每个点都是画出来的。**数据越稀疏，这个误导越强**，
> 而「每天消耗多少 Token」正是最稀疏的那一类。
>
> 柱状图没有这个问题：柱子之间什么都不画，柱高直接可比。
>
> - **必须设 `barMaxWidth`**：近 7 天只有 7 根柱子，不限宽的话每根能摊到一百多像素，
>   看着像色块而不是柱状图。
> - **0 值不显示柱子**，这是柱状图的标准行为 —— 配合卡片提示「没有调用的
>   日子按 0 计」语义是清楚的。
> - `type` 仍是 prop（默认 `line`），其他分析页想要折线不受影响。
> - 30 天实测可用：x 轴标签会自动稀疏成每两天一个。

> ⚠️ **实现修订（2026-10-12）：概览页去掉「最近调用」块，趋势图吃掉剩余高度。**
>
> 想查最近调用直接去「调用日志」页 —— 那里的筛选和分页比概览页塞 5 行强，
> 概览页也因此一屏放得下。后端对应的 `recent_logs` 字段和那次独立查询
> 一并删除（见[设计 03 §2.2](03-项目监控中心.md)）。
>
> 趋势图高度不再写死：`clamp(260px, calc(100vh - 460px), 520px)`。
> 460 是顶栏 + tabs + 统计卡片 + 留白的实测值 —— 写死像素高度的话，
> 屏幕矮的人要滚动才看得见 x 轴（视觉上像是图被截断了），屏幕高的人图又小得空荡。
> 容器尺寸变化由 `ResizeObserver` 接住（§5.1），窗口缩放后图会自己重画。

> ⚠️ **实现修订（2026-10-12）：概览页加「成本趋势」和「模型使用占比」（方案 A）。**
>
> 页面结构：统计卡片 → Token 趋势（整宽）→ 一行两列（成本趋势 + 模型占比）。
>
> **成本趋势排在半宽不是空间不够，是有意的**：它和 Token 趋势是同一份数据的两
> 种度量，并排才看得出「用量涨了但花销没涨」（换了便宜模型）或者反过来。
> 分成上下两屏就永远对不上了。
>
> `.charts` 用 `repeat(auto-fit, minmax(360px, 1fr))`：窄屏自动堆成一列 ——
> 硬写两列的话，半宽的趋势图连 x 轴标签都放不下。

### 5.3 模型占比为什么不用 ECharts

`components/ModelUsageChart.vue` 是一张**纯 CSS 的横向条形图**，没走 ECharts。
三个理由，按重要性排：

- **模型名是变长文本**：`deepseek-chat`、`BAAI/bge-m3`、`claude-sonnet-4-5-20250929`。
  ECharts 的轴标签得自己处理截断和换行；HTML 一个 `text-overflow: ellipsis`
  加 `title` 就够了，悬停还能看全名。
- **数值直接写在条子旁边**，不需要 tooltip 中转。ECharts 的 tooltip 是为
  「屏幕上放不下数字」准备的，这里放得下。
- **没有动画和交互需求**：就是几根条子按百分比设宽度。ECharts 已经在包里了
  （TrendChart 拉的），再加一个图**不增加体积**，但要多写几十行 grid / axis /
  series 配置，而这些配置在这里一条都用不上。

配色仍然读 `tokens.css` 的变量，所以看起来和旁边的趋势图是一套。

> 三口径切换的百分比**全部来自服务端**（`call_percentage` / `token_percentage` /
> `cost_percentage`）—— 前端不拿 calls / cost 现算，理由见
> [设计 03 §2.4](03-项目监控中心.md)。
>
> 切换口径时**列表按新口径重排**：切到「成本」却还按调用次数的顺序排，
> 条子一长一短没有规律，等于让用户自己找哪根最长。

| `ModelUsageChart` | 模型使用占比（三口径切换的横向条形图，见 §5.3） | ✅ 阶段 11 |
| `LogDetailDrawer` | 调用详情抽屉（日志页与异常页共用，见 §2.2） | ✅ 阶段 9 批次 2 |

| `EmptyState` | 空状态（无数据 / 无项目） | ❌ 没做成组件 |
| `LoadingWrapper` | 加载中 / 错误 / 空 三态统一处理 | ❌ 没做成组件 |

> ⚠️ **实现修订**：后两个没抽。它们最终只是 `styles/components.css` 里的
> `.empty` / `.loading` 两个类 —— 三态是**分支**不是**包装**，封成组件的话
> 要么把每个页面的三种内容都塞进插槽（用起来比直接写 v-if 还长），
> 要么做成一个只认固定文案的组件（等于没抽）。等第三个页面出现同样的
> 三态结构时再回头看。

### 6.1 ⚠️ `TimeRangePicker` 的职责

它输出的是 `start_date` / `end_date` 两个值（对应[设计 03 §2.1](03-项目监控中心.md)的接口约定），
快捷选项的映射逻辑**封装在组件内部**。

> 这样每个页面用起来都是一行，而且"近 7 天"的定义全站统一。

> ⚠️ **实现修订（阶段 11）：规则落在 `utils/timerange.ts`，组件只是它的壳。**
> 组件管界面，`buildTimeRange()` 管换算。分开放是因为调用记录页要在发请求前
> 拿到那两个值（它不改用组件的输出也能算），而且这条规则值得单独被测试。
>
> 两条必须记住的约定：
>
> - **区间左闭右开 `[start, end)`**，右端是**用户选的最后一天的次日 0 点**，
>   不是当天 `23:59:59.999`。后端一律用 `< end_date`（[设计 03](03-项目监控中心.md)、
>   [设计 04](04-调用日志与详情.md) 两个接口都是）。传 23:59:59.999 会漏掉
>   那一毫秒到午夜之间的记录，而且两个接口要各写一套边界，迟早写错一边。
>
> - **换算在前端做**，服务端拿到的是两个绝对时刻（ISO 串，带 Z）。服务端不知道
>   用户在哪个时区，"今天 0 点"对它是句歧义话。所以 `'2026-10-01'` 这种裸日期
>   必须补上时间部分再 `new Date()` —— 只写日期的话浏览器按 **UTC** 解析。
>   分桶时区则单独用 `tz` 参数传给后端，值取
>   `Intl.DateTimeFormat().resolvedOptions().timeZone`，由 `api/stats.ts` 统一注入。
>
> 实测：本地 UTC+8、2026-10-12 选「近 7 天」，发出去的是
> `tz=Asia/Shanghai&start_date=2026-10-05T16:00:00.000Z&end_date=2026-10-12T16:00:00.000Z`
> —— 正好是本地 10-06 00:00 到 10-13 00:00。

> ⚠️ **实现修订（2026-10-12）：组件新增 `maxDays`，`buildTimeRange` 新增 `granularity`。**
>
> - **`maxDays` 是自定义范围的跨度上限，只在概览页传（`OVERVIEW_MAX_DAYS = 30`）**，
>   日志页不传即不限 —— 它是分页列表，翻半年前的数据是合理需求。
>   这个数定义在 `utils/timerange.ts`，页面和组件引用的是同一个常量：
>   抄成字面量的话，改一处漏一处**不会报错**。
>   超限时**不发请求**，只在日期框描红边 + 提示一句。后端也会拒（422），
>   但 422 的报错对用户没有意义。
>
> - **`granularity` 由跨度决定，不由页面判断**：正好一个本地日历日 → `hour`，
>   否则 `day`。判定放在 `buildTimeRange` 里，因为它和时间范围是同一个概念 ——
>   页面各自去判断，迟早有一个页面判错。概览页把它随 query 一起发给统计接口
>   （[设计 03 §2.1](03-项目监控中心.md)）；日志页只取 `start_date`/`end_date`。
>
> - 概览页趋势图的**卡片提示文案跟着粒度变**（「按天/按小时统计，没有调用的…按 0 计」），
>   而且取自「上次真正加载用的粒度」，不是实时从选择器推导 —— 自定义范围两头
>   没填全时 `buildTimeRange` 返回 `null`，实时推导会让文案和已画出的图对不上。
>
> - 图表的**轴标签和 tooltip 是两套格式**：轴要短（按天 `10-06`、按小时 `14:00`），
>   tooltip 不比轴拥挤，补全更好认（`2026-10-12 14:00`）。`date` 字段是标签
>   不是时刻，**不要去 `new Date()` 解析**（[设计 03 §2.3](03-项目监控中心.md)）。

### 6.2 空状态比想象中重要

第一次使用的用户看到全是空白页面，会怀疑系统坏了。

```text
无项目 → "还没有项目，创建第一个项目" + 按钮
无数据 → "暂无调用记录，接入 API 后这里会显示数据"
样本不足 → "数据太少，暂时无法分析异常"
```

> 后两种要**区分开** —— 和[设计 05 §4.2](05-异常分析.md) 的 `baseline_available` 对应。

### 6.3 简报条与状态角标

`BriefingBar` 把概览页这一屏的数字说成一句人话。颜色四档，**判定按顺序来**：

| 语气 | 什么时候 | 色 |
|---|---|---|
| `bad` | 有 `error` 或 `error_rate` 异常 | 红 |
| `warn` | 只有 token / latency 异常 | 琥珀 |
| `ok` | 没有异常，且基线可用 | 绿 |
| `mute` | 基线不可用（样本不够） | 灰 |

> `mute` 这一档是重点：**样本不够时不许用绿色**。绿色等于说"一切正常"，
> 而真实情况是"还没开始判"—— 文案也跟着说「数据还在积累，暂时无法判断有没有异常」。
> 空状态同理（见 §6.2），连图标都从绿对勾换成灰时钟。

统计卡角标（`StatCard` 的 `chip` 插槽）三条规矩：

- **有话要说才挂**：有异常挂琥珀 / 红，基线不可用挂灰「样本不足」，其余情况**不挂**。
  给一个没检测过的指标发「正常」合格证，比不显示更糟。
- **预估成本不挂**：它不参与异常判定（阈值只定义了 token / latency / error_rate）。
  挂一个只会是摆设的角标，用户会以为那一项也被检查过。
- **角标要按类型给**，所以概览接口返回 `anomaly_counts`（四类各一格）而不是一个总数 ——
  一个总数说不出"是哪项不对"，给四张卡分不出来。改造原因见[设计 05 §8](05-异常分析.md)。

```text
近 7 天调用 188 次，比上一周期少 11.3%。Token 用了 120.3万，分布在 6 个模型上。
26 次调用失败、1 天的错误率偏高、9 次调用的 Token 明显偏高、16 次调用响应异常慢，
建议看一眼。 查看异常 ›
                                                     数据更新于 18:27
```

> 措辞按「哪几类真的发生了」挑，不按四格全列一遍 —— 写「0 次调用失败」是废话。
> 环比低于 5% 不写（噪声），模型占比不到 70% 不说"集中在谁"，改说"分布在 N 个模型上"。

### 6.4 ⚠️ 模板里的换行是一个空格

中文句子在模板里这么换行，浏览器上会多出一道缝：

```html
<strong>5 次</strong>
，比上一周期
```

Vue 的 `whitespace: 'condense'` 只丢弃**两边都不是文本节点**的那些空白节点
（元素、注释、插值都算"非文本"）；只要有一边是字面文本，换行就被留成一个空格。
于是渲染出「5 次 ，比上一周期」—— 标点前多一个空格，中文排版里看得见。

两条写法：

- **中文标点紧贴上一个标签**，一句带标点的话尽量一行写完（长就长）
- **中英文之间那个空格放进字符串里**：`{{ callsChange > 0 ? '多 ' : '少 ' }}`
  —— 模板里写的会被吃掉，字符串里的不会

怎么查：`document.querySelector(...).textContent`。**别用 `innerText`** ——
它会按渲染布局在块级元素之间补空格，看起来句句都有问题。

## 7. 开发环境配置

### 7.1 跨域处理

前端开发服务器（如 `:5173`）和后端（`:8001`）不同源。

> 后端端口定 **8001** 而非默认的 8000：本机 8000 已被另一个项目的后端占用，两个要同时跑。

**用 Vite 的 proxy**：

```text
/api  →  http://localhost:8001
```

> **好处**：前端代码里写的永远是 `/api/v1/xxx`，不用管环境。
> 生产环境由 Nginx 做同样的转发，前端代码一行不改。
>
> ⚠️ 不要在前端代码里硬编码 `http://localhost:8001` —— 那样部署时必然要改代码。

## 8. 边界情况

| 情况 | 处理 |
|---|---|
| token 过期 | 拦截器捕获 401 → 清 token → 跳登录页 |
| 刷新页面 token 还在 | 从 localStorage 恢复，先请求 `/users/me` 验证有效性 |
| 请求中用户切换页面 | 组件卸载后不再 setState（或忽略） |
| 网络错误 | 统一提示"网络异常，请稍后重试" |
| 数据为空 | 走 `EmptyState`，不要显示空白 |
| 数字很大 | 要读数的地方用完整数字 `11,391,234`；只有图表 y 轴刻度用缩写 `1139.1万` |
| 金额精度 | 后端返回数字，前端格式化时**不要做运算** |

> **金额不做前端运算**：`0.1 + 0.2` 在 JS 里同样有浮点问题。
> 需要"占比""合计"这类计算，一律由后端返回（见[设计 03 §2.4](03-项目监控中心.md)）。

> ⚠️ **实现修订（2026-10-12）：大数字只在图表 y 轴刻度上用缩写。**
>
> `formatCompact` 把 `11,391,234` 压成 `1139.1万` —— **它是精确值的缩写，不是估算**，
> 但四舍五入到万位就是丢了后四位。指标卡、tooltip、表格这些用户要**读数**的地方
> 一律用 `formatNumber`。理由是用户看到「1139.1万」的第一反应是"这是估的吧" ——
> 一个监控数字被当成估计值，卡片就白做了。
>
> 只有 y 轴刻度保留缩写：完整数字会把左边距吃到十几厘米宽，网格区域被挤没，
> 而轴的作用本来就是读量级，精确值有 tooltip 兜着。
>
> 由此 `formatCompact` 的适用范围收窄到图表组件内部（`TrendChart.vue` 的 y 轴），
> **页面上不该再出现它**。
