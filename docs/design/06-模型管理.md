# 设计文档 06：模型管理

> 对应需求：[06-模型管理](../requirements/06-模型管理.md)
> 对应阶段：**阶段 7**

------

## 1. 两类模型

`models` 表里同时存两种记录，靠 `is_builtin` 和 `owner_id` 区分：

| | 内置模型 | 用户自建模型 |
|---|---|---|
| `is_builtin` | true | false |
| `owner_id` | null | 用户 id |
| 谁能看 | **所有用户** | 只有创建者 |
| 谁能改 | 谁都不能 | 只有创建者 |
| 从哪来 | 初始化脚本写入 | 用户自己添加 |

> **这是"共享数据 + 私有数据"共存的典型模式**：一张表装两种数据，用 `owner_id` 是否为 null 区分所有权。
>
> 它带来一个必须记住的规则：**查询时的过滤条件是 `is_builtin = true OR owner_id = 当前用户`**，
> 不是简单的 `owner_id = 当前用户`。漏掉前半段，用户就看不到内置模型了。

## 2. API 接口

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/v1/models` | 可用模型列表（内置 + 自己的） |
| POST | `/api/v1/models` | 新增自建模型 |
| GET | `/api/v1/models/{model_id}` | 详情 |
| PATCH | `/api/v1/models/{model_id}` | 修改（仅自建） |
| DELETE | `/api/v1/models/{model_id}` | 删除（仅自建） |

### 2.1 列表响应

```json
{
  "items": [
    {
      "id": 1,
      "provider": "deepseek",
      "model_name": "deepseek-chat",
      "input_price": 1.0,
      "output_price": 2.0,
      "is_builtin": true,
      "status": "active"
    },
    {
      "id": 7,
      "provider": "openai",
      "model_name": "my-finetuned-model",
      "input_price": 5.0,
      "output_price": 15.0,
      "is_builtin": false,
      "status": "active"
    }
  ],
  "total": 2
}
```

### 2.2 创建请求

```json
{
  "provider": "openai",
  "model_name": "my-finetuned-model",
  "input_price": 5.0,
  "output_price": 15.0
}
```

**字段校验**：

| 字段 | 规则 |
|---|---|
| provider | 非空，≤ 50 字符 |
| model_name | 非空，≤ 100 字符 |
| input_price | ≥ 0，最多 6 位小数 |
| output_price | ≥ 0，最多 6 位小数 |

> **价格允许为 0** —— 有些模型是自部署的，成本不计入。
> 但不允许为负 —— 负价格会让成本统计出现负数。

## 3. 隔离与权限（本模块最容易出错的地方）

### 3.1 ⚠️ 内置模型必须拒绝修改

```text
PATCH /api/v1/models/1  （id=1 是内置模型）
→ 必须拒绝
```

**如果只在"列表"接口过滤了 `is_builtin`，而修改接口没校验，任何人改一下 URL 就能篡改内置价格** ——
而内置模型是所有用户共享的，改一次影响所有人。

> 这是一个"读接口做了隔离，写接口忘了"的典型越权 bug。
> **规则：凡是涉及权限的校验，要在每个需要它的接口上独立检查**，不能指望"列表接口过滤过了"。

### 3.2 修改 / 删除的校验链

```text
① 按 model_id 查模型
      不存在 → 404
② is_builtin == true → 404（不是 403，不暴露它是内置的）
③ owner_id != 当前用户 → 404
④ 通过
```

> 第 ③ 步复用 [01-用户与项目管理](01-用户与项目管理.md) 的思路 —— **越权一律 404**。
>
> 建议抽成一个 `get_own_model` 依赖，让所有涉及单个模型的接口都套上它。

### 3.3 删除模型前要考虑的问题

**如果这个模型已经被 `llm_requests` 引用（有历史调用记录），能删吗？**

| 方案 | 后果 |
|---|---|
| A. 直接删 | 历史记录里 `estimated_cost` 已经算好了，不受影响；但以后再上报这个模型就查不到价格了 |
| B. 改为 `status = disabled` | 不影响历史，新上报不再匹配到价格 |

**V1 选 B**：DELETE 接口实际执行"禁用"，而不是物理删除。

> **理由**：模型价格是历史数据的一部分。物理删除会让"这个模型明明用过，怎么列表里没有"变得无法解释。
> 禁用既达到了"不再使用"的目的，又保留了历史。

### 3.4 关于 `provider` + `model_name` 的唯一性

同一用户不应添加两个同名模型（会有歧义：到底用哪个价格？）。

**约束**：同一 `owner_id` 下 `model_name` 唯一。

⚠️ 内置模型也会匹配 —— 如果用户添加的 `model_name` 和某个内置模型同名，上报时会匹配到两条记录。

**处理**：创建时校验"不能与任何可见模型同名"，冲突返回 400。

## 4. 与成本计算的关系

本模块的存在意义就一个：**为上报接口提供价格**。

```text
POST /api/v1/logs
   ↓
拿 model 字段 → 查 models 表
   ↓
WHERE model_name = :model
  AND status = 'active'
  AND (is_builtin = true OR owner_id = <项目的 owner_id>)
   ↓
找到 → 算 cost
找不到 → cost = null
```

### 4.1 ⚠️ 如果一个 model_name 匹配到多条怎么办

比如内置模型有个 `gpt-4`，用户又自己加了一个叫 `gpt-4` 的（虽然创建时校验了，但历史数据可能已经有）。

**处理：优先匹配用户自建的**（更具体、更贴合用户意图）。

```text
ORDER BY is_builtin ASC   -- false 在前（用户自建优先）
LIMIT 1
```

> 这条规则要写在代码注释里 —— 否则以后有人看到 `ORDER BY` 会疑惑为什么这么排。

### 4.2 价格改动不影响历史

`llm_requests.estimated_cost` 是**写入时快照**。改模型价格，只影响之后的调用。

> 这是需求文档 13.2 定下的规则，也是符合用户心智的：
> 用户不会希望"我改了价格，上个月的成本报表也跟着变了"。

## 5. 边界情况

| 情况 | 处理 |
|---|---|
| 修改内置模型 | 404 |
| 修改别人的模型 | 404 |
| 删除已被调用的模型 | 执行禁用（status = disabled） |
| 与已有模型重名 | 400 |
| 价格为负 | 422（schema 校验） |
| 价格小数位过多 | 422 或四舍五入（建议直接约束 ≤ 6 位） |
| 列表为空（无内置也无自建） | 空数组 + total = 0（初始化脚本应保证有内置模型） |

## 6. 初始化脚本

内置模型需要一个初始化脚本写入，**放在和播种脚本同一个目录**：

```text
ai-monitor-backend/scripts/init_models.py
```

内容：写入 V1 支持的主流模型及价格（deepseek-chat、gpt-4o 等）。

**脚本要求**：

```text
✅ 幂等 —— 重复执行不产生重复记录（按 model_name + is_builtin 判断）
✅ 独立 —— 不依赖数据库里已有数据
```

> **幂等很重要**：开发过程中你会反复跑这个脚本。不幂等的话，跑几次数据库里就有几份重复的内置模型，
> 而且价格可能不同 —— 成本计算会随机匹配到其中一个。

## 7. 实现顺序建议

```text
① models/model.py        表定义
② schemas/model.py       请求/响应模型
③ services/models.py     查询（含可见性过滤）+ 增删改
④ deps.py                新增 get_own_model 依赖
⑤ api/models.py          路由
⑥ scripts/init_models.py 内置模型初始化
```

> ⑥ 要**早写** —— 阶段 6 的上报接口需要它来算成本，没有内置模型数据，成本全是 null。
