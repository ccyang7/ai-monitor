# 模块九：前端页面

> 对应开发阶段：**阶段 10（Vue 前端）**。

------

## 1. 页面结构

V1 围绕 **首页 → 项目 → 项目监控中心** 的路径设计。

```text
/
├── Login
│
├── Home
│   ├── 用户信息
│   ├── 我的项目
│   └── AI 助手（可唤起）
│
├── Project
│   └── Project Detail
│       ├── Overview
│       ├── Logs
│       ├── Token
│       ├── Cost
│       ├── Models
│       └── Anomalies
│
├── AI Assistant       # 全局助手 —— 首页与项目页均可唤起，同一助手
│
└── Settings
    └── Model / API Key
```

------

## 2. 页面 1：首页

**定位：不是传统的大数据 Dashboard，首页主要负责展示"用户和项目"。**

核心内容：

```text
用户信息
我的项目
创建项目
AI 助手入口
```

示例：

```text
你好，开发者 👋

我的项目

┌──────────────────────────────┐
│ 🤖 AI知识问答                 │
│ Python · DeepSeek            │
│ 最近调用：刚刚                │
│ ● 运行正常                   │
│                              │
│ 查看项目 →                   │
└──────────────────────────────┘
```

首页重点是：

```text
我是谁
我有什么项目
项目现在是否正常
```

**而不是**：

```text
所有项目加起来用了多少 Token
所有项目加起来花了多少钱
```

> 首页**不展示**复杂的全局 Token / Cost Dashboard。
> 首页的 AI 助手入口与项目页的是**同一个助手**，区别仅在于是否带入"当前项目"这个上下文提示。

## 6. 页面 5：AI 分析（全局助手）

```text
首页 / 项目页
 ↓
唤起 AI 助手
 ↓
（可选）带入当前页面上下文
 ↓
Tool Calling
 ↓
查询真实数据（限当前用户）
 ↓
分析
 ↓
给出结论
```

详见《[07-AI分析助手](07-AI分析助手.md)》。

### 6.1 交互要求

| 要求 | 说明 |
|---|---|
| **流式输出** | 多轮工具调用延迟叠加，必须流式，否则用户盯着转圈 20 秒 |
| **过程可见** | 工具调用时显示状态（"正在查询今日数据…"），让用户知道助手在工作 |
| **上下文提示** | 在项目页唤起时，界面上应有提示"当前上下文：项目 A" |

## 8. UI 原则

### 8.1 人话优先

```text
✅ Token 使用量      ❌ Token Consumption Metrics
✅ 响应时间          ❌ P95 Latency
```

### 8.2 先结论，后数据

```text
今天费用增加 32%

主要原因：
单次请求 Token 增加
```

而不是先展示十张图让用户自己分析。

### 8.3 默认简单，按需深入

```text
首页
 ↓
项目
 ↓
项目监控中心
 ↓
日志
 ↓
详情
 ↓
高级信息
```

### 8.4 不要图表墙

> **不要因为使用 ECharts 就把项目监控中心变成"图表墙"。**

UI 应该保持：**轻量、简洁、低信息密度。**

判断标准：每加一个图表，问一句"它帮用户回答了什么问题？"——答不上来就不加。

## 9. 验收标准

- [ ] 登录页可用
- [ ] 首页显示用户信息与项目列表
- [ ] 首页可以创建项目
- [ ] 首页可以进入项目
- [ ] 首页有 AI 助手入口
- [ ] 项目页有完整的分页签导航
- [ ] 调用记录页支持筛选与搜索
- [ ] 调用详情页展示完整信息
- [ ] 设置页可以管理模型与 API Key
- [ ] AI 助手可以流式输出
- [ ] 整体信息密度低，没有无意义的图表

------

## 10. 技术选型

```text
Vue 3 + TypeScript + Vite
Ant Design Vue（或 Element Plus）
ECharts（仅用于必要的趋势图）
```

> 阶段 10 是**从后端到前端的陡坡**（语言、生态、思维模式全换）。
> 建议策略：不追求设计感，组件拼装为主；一次只做一个页面的一个区块，每步都能看到成果。
