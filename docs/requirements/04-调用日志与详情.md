# 模块四：调用日志与详情

> 对应开发阶段：**阶段 6（日志入库）、阶段 9（列表 / 筛选 / 搜索）**。

------

## 1. 模块目标

展示当前项目的**所有大模型调用记录**，并支持定位到具体某一次调用。

用户能回答的问题：

```text
这次调用用了什么模型？
输入输出是什么？
消耗了多少 Token？
耗时多久？
成功了还是失败了？
```

------

## 2. 日志列表

### 2.1 定位

> **默认只显示当前项目的数据。**

这是隔离区的一部分 —— 每个查询都必须带 `project_id` 过滤。

### 2.2 列表字段

| 字段 | 说明 |
|---|---|
| 时间 | 调用时间 |
| 模型 | 使用的大模型 |
| 输入 Token | 输入 Token |
| 输出 Token | 输出 Token |
| 总 Token | 总 Token |
| 耗时 | 请求耗时 |
| 状态 | 成功 / 失败 |
| 成本 | 本次调用成本 |

### 2.3 分页

日志量大，**必须分页**（V1 用 Offset 分页即可）。默认按时间倒序。

------

## 3. 筛选

支持：

```text
模型
时间范围
状态（成功 / 失败）
Token 范围
```

筛选条件的组合会体现在 SQL 的 `WHERE` 中，注意与 `project_id` 条件是 **AND 关系**，不能互相覆盖。

------

## 4. 搜索

支持根据以下内容搜索：

```text
用户输入（input）
AI 输出（output）
模型名称
```

### ⚠️ 实现提示（性能）

`input` / `output` 是**大文本字段**，直接用 `LIKE '%关键词%'` 会触发**全表扫描**，数据量增长后查询会明显变慢。

V1 数据处理方式：

- 数据量可控，可以先这样实现，但要知道这个瓶颈存在
- 后续优化方向：PostgreSQL 的 `pg_trgm` 扩展 + GIN 索引，或全文检索（`tsvector`）

> 不要因为"能跑"就忽略这个问题 —— 它是**已知的**技术债，不是意外。

------

## 5. 调用详情

点击某条日志后进入详情页。

### 5.1 基础信息

```text
调用详情

项目：   AI知识问答
模型：   DeepSeek
时间：   2026-10-06 11:42:31
耗时：   1.82s
状态：   成功
```

### 5.2 Token 信息

```text
输入：    382
输出：    901
总计：  1,283
```

### 5.3 用户输入

```text
用户输入

什么是 Redis？
```

### 5.4 AI 输出

```text
AI 输出

Redis 是一种开源的...
```

### 5.5 错误信息（失败时）

```text
请求失败

错误类型：API Timeout
错误信息：Request timeout after 30s
```

------

## 6. 数据模型对应

详情页对应 `llm_request` 表的全部字段：

```text
id
project_id
provider
model
input
output
input_tokens
output_tokens
total_tokens
latency
status
error_message
estimated_cost
created_at
```

## 7. 验收标准

- [ ] 可以查看当前项目日志
- [ ] 日志按时间倒序，支持分页
- [ ] 可以按模型筛选
- [ ] 可以按时间范围筛选
- [ ] 可以按状态筛选
- [ ] 可以按 Token 范围筛选
- [ ] 可以搜索用户输入内容
- [ ] 可以搜索 AI 输出内容
- [ ] 可以查看调用详情
- [ ] 详情页可以查看输入、输出、Token、耗时、错误信息
- [ ] **日志页面不会出现其他项目的数据**
