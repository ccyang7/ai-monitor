# 模块一：用户与项目管理

> 对应开发阶段：**阶段 3（项目管理 API）**，登录认证部分在阶段 3 一并完成。

------

## 1. 模块目标

平台的基本单位是 **Project**。本模块负责：

- 用户注册 / 登录
- 项目的创建、查看、删除
- 项目 API Key 的生成与管理（供数据上报使用）
- 项目数量上限控制

------

## 2. 用户

### 2.1 用户信息

V1 只需要最简信息，不做复杂个人中心。

```text
id
username
password_hash      # 存哈希，绝不存明文
email
created_at
updated_at
```

### 2.2 认证

- 用户登录后获得凭证（V1 用 JWT 即可，不上 OAuth）
- 后续所有接口通过凭证识别**当前用户** —— 这是用户隔离的起点

> ⚠️ 用户隔离的三层实现中的第一层就是这里：请求 → 解析出 `current_user_id`。没有它，后面两层都是空谈。

------

## 3. 项目

### 3.1 项目概念

一个 Project 对应一个实际的 AI 应用，例如：

```text
AI知识问答
AI网站生成平台
AI客服
```

一个项目是**平台进行监控、分析和 AI 解读的基本单位**。

### 3.2 项目字段

```text
id
owner_id           # 归属用户 —— 用户隔离的基础，不可省略
name
description
status
created_at
updated_at
```

### 3.3 项目列表

首页展示当前用户的项目卡片：

| 字段 | 说明 |
|---|---|
| 项目名称 | AI 项目名称 |
| 技术栈 | 例如 Python |
| 默认模型 | 例如 DeepSeek |
| 最近调用 | 最近一次调用时间 |
| 状态 | 正常 / 异常 |

### 3.4 创建项目

用户填写：

```text
项目名称
项目描述
技术栈
```

创建完成后生成：

```text
Project ID
Project API Key
```

### 3.5 项目数量上限

V1 每个用户**同时最多拥有 3 个活跃项目**。

- 限制值通过**配置项**控制（不硬编码在业务代码中），便于后续调整
- 删除项目后释放配额，可以再创建新项目
- 创建接口在写入前校验当前项目数量，超限时返回明确的错误信息

------

## 4. API Key

### 4.1 用途

API Key 用于**数据上报接口**识别项目身份（见模块二）。

不同项目拥有独立的 API Key：

```text
AI知识问答 → Project A 的 Key
AI网站生成  → Project B 的 Key
```

### 4.2 字段设计

```text
id
project_id
key_hash           # 存哈希，不存明文
key_prefix         # 用于界面展示识别，如 proj_a1b2...
status
created_at
expired_at
```

### 4.3 生成要求

- 使用**密码学安全**的随机数生成（Python `secrets` 模块）
- **不可预测、不可枚举** —— 它等同于密码
- 一个项目可以拥有一个或多个 API Key

> ❌ 不要用自增 ID、时间戳、雪花算法等方式生成 Key —— 那些是可预测的，等同于把密码设成"123456"。

------

## 5. 用户隔离（本模块的核心约束）

隔离不是一个点，而是一条**贯穿请求链路的约束**。任何一个环节漏了，隔离就破了。

```text
① 认证层：请求 → 解析出 current_user_id
② 数据层：所有查 Project     → WHERE owner_id = current_user_id
          所有查监控数据      → 先确认所属 project 属于 current_user
③ AI 工具层：project_ids 参数 → 校验每一个都属于 current_user
```

### 实现建议：抽成 FastAPI 依赖，不要每个接口手写

```python
# 示意：写一次，所有接口自动带上
def get_own_project(project_id: int, user = Depends(get_current_user)) -> Project:
    # ① 项目存在吗？ ② 项目属于当前用户吗？
    # 任一不通过，直接抛错
    ...

@app.get("/projects/{project_id}/logs")
def get_logs(project: Project = Depends(get_own_project)):
    # 到这里 project 一定存在、且一定属于当前用户
    ...
```

**"不可能漏"比"记得别漏"可靠得多。**

### ⚠️ 需要提防的：IDOR

前端路由是 `/projects/3/logs`，用户把 `3` 改成 `4` —— 后端必须校验项目 4 属于当前用户。

这类漏洞不需要任何攻击技术，改个数字就行。所以每个涉及项目的接口都需要**两层校验**：

```text
① project 4 存在吗？
② project 4 属于当前登录用户吗？   ← 很多人只写了①
```

------

## 6. 验收标准

- [ ] 可以注册 / 登录
- [ ] 可以创建项目
- [ ] 可以删除项目
- [ ] 可以查看项目
- [ ] 可以生成 API Key
- [ ] 超出项目数量上限（默认 3 个）时，创建被拒绝并返回明确错误
- [ ] 删除项目后释放配额，可以再创建
- [ ] 不同项目的数据相互隔离
- [ ] **不同用户的数据相互隔离**（改 URL 里的 project_id 无法访问他人项目）
- [ ] 访问不存在的项目 / 不属于自己的项目，返回 404 而非 403（不泄露资源是否存在）
