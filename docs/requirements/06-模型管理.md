# 模块六：模型管理

> 对应开发阶段：**阶段 7（Token / Cost 统计）**，与成本计算强相关。

------

## 1. 模块目标

平台**不与任何模型厂商强绑定**。

V1 设计为支持：

```text
DeepSeek
OpenAI
Qwen
Claude
其他 OpenAI 兼容模型
```

用户可以在设置页配置模型和价格，平台据此计算成本。

------

## 2. 模型信息

每个模型记录：

```text
Provider        例如 DeepSeek
Model Name      例如 deepseek-chat
输入价格         xxx / 1M Token
输出价格         xxx / 1M Token
```

展示示例：

```text
DeepSeek Chat

Provider：   DeepSeek
Model：      deepseek-chat
输入价格：   2 元 / 1M Token
输出价格：   8 元 / 1M Token
```

------

## 3. 数据模型

```text
id
provider
model_name
input_price
output_price
is_builtin         # true = 系统预置
owner_id           # 预置模型为 null，用户自建的为自己的 id
status
created_at
updated_at
```

> 原设计中的独立 `ModelPrice` 表已合并进本表 —— 价格是模型的属性，拆成两张表没有收益。

------

## 4. 归属规则（重要）

这是**跨用户隔离**在模型层面的体现：

```text
可用模型 = 系统预置（is_builtin = true）
         ∪ 当前用户自建（owner_id = 当前用户）
```

### 为什么需要这个设计

如果所有模型都是纯全局的：

> 用户 A 修改了「deepseek-chat」的价格 → 用户 B 的成本统计**跟着变**，且 B 找不到原因。

这是典型的**跨用户数据污染**。

### 正确做法

```text
系统预置模型：所有用户可见，但用户不能直接修改
用户修改预置价格时：复制一份成为自己的模型（owner_id = 自己）
用户自建模型：仅自己可见
```

查询可用模型时的条件：

```sql
WHERE is_builtin = true OR owner_id = :current_user_id
```

------

## 5. 自定义模型

允许用户添加：

```text
模型名称
Provider
输入 Token 价格
输出 Token 价格
```

这样未来更换模型时**无需修改系统核心代码**。

------

## 6. 与成本计算的关系

成本在**日志写入时**按当时的模型价格计算快照（见模块三）：

```text
estimated_cost = input_tokens  / 1_000_000 × input_price
               + output_tokens / 1_000_000 × output_price
```

**价格匹配方式**：上报的 `model` 字段（如 `deepseek-chat`）与 `model.model_name` 匹配。

### ⚠️ 需要处理的边界情况

| 情况 | 处理建议 |
|---|---|
| 上报的模型在模型表中不存在 | 成本记为 0 或 null，**不要报错**（不能因为价格没配就拒绝日志） |
| 用户改了价格 | 只影响之后写入的日志，历史成本不变 |

------

## 7. 验收标准

- [ ] 支持多个模型
- [ ] 支持模型价格配置
- [ ] 可以计算预计成本
- [ ] 可以查看项目模型使用情况
- [ ] 系统预置模型用户不可直接修改
- [ ] 用户修改预置价格时生成自己的副本
- [ ] 用户之间的模型配置互不影响
- [ ] 未知模型不导致上报失败
